### シーズン機能は「なくす」という選択肢がない

- **`achieve-mission.ts:293-299`** — `is_active: true` のシーズンが取れないと
  `"Current season not found"` で**ミッション達成が丸ごと失敗する**
- **`src/lib/services/seasons.ts:13`** — `.eq("is_active", true).single()`。
  active が **0本でも2本以上でもエラー**。常にちょうど1本必要
- `season_id` は `achievements` / `xp_transactions` / `user_levels` / `user_badges` の4テーブルに FK
  （カラムは nullable だが、書き込み側が必須扱い）
- ランキングのDB関数はすべて `p_season_id` 引数を取る（8本以上）
- アプリ側で `season_id` を参照しているファイルは **28本**

→ **「一旦シーズンの話はなし」は仕組みを残したまま実現する**。触るのは YAML の3行だけ。
そして MTG の「11月末で1回閉じて、来年またアップデートして帰ってくる」が**シーズン制度そのもの**なので、
後から必ず要る。**消さないのが正解**。

### 注意点（ハマりどころ）

1. **`pnpm run season:sync` は upsert のみで、削除しない**（`season_data/src/sync.ts:67`）。
   YAML から `season1`/`season2` を消しても、**既存DBのレコードは残る**。
   → 浜通り用 Supabase はこれから新規作成なので**実害なし**（YAMLにない = 最初から作られない）。

4. 現状の名前を放置すると、フッターの「過去シーズン」（`src/components/footer/seasons-list.tsx`）に

## D. 非表示にする手段（このコードベースで使えるもの）

1. **ミッション単位** — `mission_data/missions.yaml` の `is_hidden: true`
   → 一覧から消え、詳細ページも 404（`src/app/missions/[slug]/page.tsx:91,106`）。データは残る。**最も安全で可逆**
2. **ページへの導線** — `src/components/common/navbar.tsx`（ドロップダウンにマップ3種）、`src/app/page.tsx` のセクション、`src/app/footer.tsx`
   → **ルートは生きているので直リンクでは見える**。βではこれで十分
3. **UI だけ塞ぐ** — `src/app/xxx/page.tsx` を削除し `src/features/` は温存。実装を残したまま完全に見えなくする中間手段
